# Issue#281 供料产物替换缺陷：跨页切开实体漏替换 + 类型标签叠字

> 关联 Issue：<https://github.com/youayou-Lee/LexMask/issues/281>
> 状态：修复 + 单测 + 本地真卷重跑验证完成（分支 `fix/issue281-agent-md-pagesplit`），待评审/合并。

## 背景

供料模式（Agent MD）把 zip 官方结构化 md 作为产物载体、把拍平 segs 作为检测面（Issue#248 替换式改造）。两者在页边界上的表示不同：

- 结构化 md：页间是「页脚数字 + `<!-- page N of M -->`」；
- 检测面 segs：页间只有 `\n\n`。

实体原文恰好被页边界切成两半时（上一页末前半、下一页首后半），产物侧不存在连续形态，`render_outputs_on_structure` 的字节级 `replace` 与空白柔性正则（flex）都匹配不到。

## 根因（三条）

1. **表示失配**：页边界噪声穿插在实体中间，plain/flex 两种匹配都只认「连续/仅空白差」形态。
2. **两道闸双假绿**：覆盖闸判「映射项原文是否出现在 md」，残留闸判「替换后原文是否仍在 md」。同一事实的 OCR 空白变体项（更长的 flex 项）按长度降序先替换掉唯一连续形态后，被切开的项既「不缺席」（连续形态存在于别处）也「不残留」（切开形态不是逐字原文）——真实标识因此出厂。
3. **标签叠字**：`build_mapping_draft` 的 replacement 固定为「类型短名+序号」；OCR 原文自带同款短名（「案号（2023）…号」）时，替换后成「案号案号N」。

## 方案

`backend/app/services/agent_md_replace.py` 两段纯逻辑，均在结构化渲染主路径生效，不改变映射表与审阅口径：

1. `_apply_page_split(md, items)`：
   - 对每个非 excluded 映射项，在**去空白后**的字符序列上枚举全部切分点 `i`；
   - 正则 = head 字符（`\s*` 连接）+ 页边界噪声（`\s*(?:\d{1,3}\s*)?<!-- page N of M -->\s*`，命名组 `pbnoise`）+ tail 字符（`\s*` 连接）；
   - 替换值 = `replacement + pbnoise`——**页边界噪声原样回插**，否则 `verify_structure_integrity` 的页标记序列对账会判结构破坏（这是本方案的关键约束）；
   - 返回 `{映射项 id: 用过的正则}`，供覆盖闸/残留闸判定。
2. `_collapse_label_duplication(md, items)`：replacement 形如「短名+序号」且「短名+replacement」在产物中真实存在时，收口为单个标签（`案号案号5` → `案号5`）；映射表 replacement 不变。legacy `render_outputs` 同样调用。
3. 闸门同步：覆盖闸对 `_split_applied` 中的项不再按「原文连续出现」判缺席；残留闸对这类项改用其切分正则复检。

## 验收

- AC1 跨页切开形态被替换为映射占位符，页标记序列/结构对账不变，连续形态替换行为不变；
- AC2 产物无「案号案号N」叠字，映射表 replacement 仍为「案号N」；
- AC3 excluded 项不受影响（跨页形态保留原文，保留清单仍记账）；
- AC4 单测全绿、零回归。

单测：`backend/tests/test_issue281_pagesplit_label.py`（6 例）。本地真卷重跑：同一 6 页扫描件、同一 30 条映射，修复后跨页项落地「案号4」（修复前 0 次）、叠字收口、6/6 页标记与结构对账通过，映射表/保留清单逐字节相同。

## 范围外（另案拍板）

- 同一事实的 OCR 空白变体各自占用一个占位符（同一案号出现两种占位符），下游 Agent 会误判为两个案件——是否在映射生成期合并，涉及映射表可见行为，待定。
- 机构名保留（ORG 默认 excluded）是既有定稿策略，本 Issue 不动；统一社会信用代码类型缺口另案。

## 第二批：五卷验收中发现的三处新缺陷

五卷真卷验收（6 页文本 / 6 页扫描 / 2 页 / 78 页 / 86 页扫描）又暴露三处同类「表示失配 / 高频命中」缺陷，均已修复：

1. **Markdown 转义与全角折半角失配（整卷拒产）**：官方结构化 md 把检测面原文做了 Markdown 转义（`wxid_fixture0000001` → `wxid\_fixture0000001`），另有全角 `：`/`）` 被半角化。字面与空白柔性都匹配不到 ⇒ 前向覆盖闸判 `representation_mismatch`，整卷不交付。修法：新增**折叠视图**——`_fold_md` 生成「去转义 + 全角 ASCII 折半角」的副本并给出折叠下标→原文下标映射（含前置转义符的回退），`_fold_flex_pattern` / `_fold_spans` / `_fold_matches` / `_replace_fold` 在折叠视图上匹配、回原文按区间倒序替换；覆盖闸、残留闸、legacy 兜底同步接入。
2. **短数字实体吃掉页标记（结构对账失败）**：扫描卷 NER 把页码片段误判成 `CASE_NUMBER='10'/'11'`，字节级 `replace` 命中 `<!-- page 10 of 86 -->` 的页号 ⇒ 页标记序列 86→84，整卷 fail-closed。修法：`build_mapping_draft` 默认排除「单字符或 ≤3 位纯数字」原文（映射表可见、律师可改）；渲染层 `degenerate_original` 硬闸同步扩容。
3. **页标记护甲**：即便有上面的排除，律师显式改 keep 或实体与页号同形时仍可能改坏页标记。修法：`_mask_page_markers` 在替换/闸门期间把页标记换成私用区哨兵（不含数字，避免被短数字项命中），覆盖闸/主循环/叠字收口/残留闸全部只认正文，返回前 `_unmask_page_markers` 逐字节还原。副作用（有意）：覆盖闸与残留闸不再把页标记里的同形文本当成「原文存在」的证据。

4. **模型召回兜底（正则补层）**：86 页扫描件验收时 NER 漏了 21 个身份证号、22 个手机号、4 个微信 ID——扫描件 OCR 文本里的长数字串召回不稳定，漏一个就是一次泄露。修法：`agent_md_ner.py` 新增 `regex_pii_entities`（ID_CARD `\d{17}[\dXx]` / PHONE `1[3-9]\d{9}` / BANK_CARD `6222\d{12,15}` / SOCIAL_ACCOUNT `wxid_[0-9A-Za-z_-]{4,}`，与 vl_md 管线同口径）与 `merge_regex_entities`：偏移沿用全局拼接口径、页码 = 段页码 + 1；仅当 NER 有「会真正打码」的实体**完整包住**补层命中时才丢弃——真卷里 NER 会产出 1 字符 `CASE_NUMBER:'4'` 压在身份证号首位，旧「区间重叠即丢」规则会让整批身份证号漏网（已补回归测试）。

验收证据（本地真卷，全部 completed）：6 页文本卷页标记 6/6、映射残留 0；6 页扫描卷与第一批修复产物逐字节相同；78 页文本卷页标记 78/78、映射残留 0（另有 2 处微信 ID 变体属检测侧未召回，非替换层缺陷）；86 页扫描卷页标记 86/86、映射残留 0。测试 `backend/tests/test_issue281_pagesplit_label.py` 共 16 例（第三批后为 24 例）；后端全量 2932 passed / 18 failed（与 preview 基线同集合）。

## 第三批：冷评审自审发现

1. **跨页两侧 OCR 易混字符变体漏替换（fail-open）**：同一实体被页边界切开时，两侧可能各带一处 OCR 混淆（`0`↔`O`、`1`↔`l`/`I`、`5`↔`S`、`8`↔`B`、`2`↔`Z`、`6`↔`G`、`9`↔`g`）。切分正则逐字相等，命中不了即静默出厂（构造样例已逐字确认）。修法：`_OCR_CONFUSABLES` + `_ocr_char_pattern` 把切分正则里每个数字/易混字母展开为互认字符类，其余字符仍 `re.escape`。
2. **残留闸里的切分判定是死判据**：页标记护甲把页注释换成哨兵，而切分正则含 `<!-- page N of M -->`，在 masked md 上必然失配 ⇒ 该分支永远为 False。修法：残留闸的切分复检改在 `_unmask_page_markers` 还原视图上跑。

边界：非易混字符的任意差异（如 `30` vs `38`）仍不覆盖——模糊相似度闸会误伤「相邻不同案号」的真卷，登记为已知边界，不在本 PR。

单测新增 2 例（易混变体与连续形态并存；仅变体切开不得误判 `representation_mismatch`），共 24 例；红性由 monkeypatch 关掉 `_ocr_char_pattern` 复得。
