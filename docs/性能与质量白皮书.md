## 1. 平台概述

本平台面向法律、医疗、金融、政务场景，提供文档（Word/PDF/图片/扫描件）与库表（CSV/Excel/JSONL/SQLite/数据库直连）两类数据的本地化匿名化处理。全链路数据不出域：识别与打码所需的 OCR、语义、视觉三类模型全部本地 GPU 部署，无任何外部 API 依赖。

## 2. 识别质量（黄金语料实测）

采用逐项标注真值的行业黄金语料，在生产环境完整识别管线上实测。判定标准：
**identity 类（姓名/证号/电话/卡号等直接标识符）漏检不可接受，门槛 100%**；standard 类（地址/机构/邮箱等）门槛 85%；行业专项标识符单列观察。

| 行业语料 | identity 召回 | standard 召回 | 行业专项召回 | 类型标注正确率 |
|---|---|---|---|---|
| 法律（合同/协议 5 份，46 实体） | **31/31 = 100%** | 15/15 = 100% | — | 100% |
| 医疗（病历/报告 4 份，33 实体） | **19/19 = 100%** | 7/7 = 100% | 病案号/住院号/门诊号 7/7 = 100% | 97% |
| 金融（审批/流水/尽调 3 份，28 实体） | **17/17 = 100%** | 8/8 = 100% | 客户号/商户号/流水号 5/5 = 100% | 100% |

质量回归机制：以上语料与门槛作为验收轨常驻代码库，任何识别管线改动导致召回下降即构建失败——识别质量与代码一样受版本控制保护。

### 3.1 单文件识别时延

| 文档类型 | 规模 | 耗时 | 说明 |
|---|---|---|---|
| 文本型 PDF | 78 页 / 45,408 字 | **32.4 s** | 三轮实测中位；19 型识别项（单文件默认）；36 次 HaS 调用 / 1,468 实体 |
| 文本型 PDF（短） | 1,858 字 / 2 块 | **7.9 s** | 同上管线 |
| 扫描型 PDF | 每页 | **中位 27 s（串行 OCR+HaS，2026-10-15 批次）** | 阶段分解见 §3.2。**随卷差异极大，下列三档分属两批语料，勿混读**：① 2026-09-14 另一批真实案卷逐文件 p50 **6.7–18.0 s**（最小 6.716 s / 最大常态 18.033 s，见 §3.5 与台账 D）；② 67 页证据卷内、含约 130 个候选框的金融票据密集页 **86–93 s**（2026-10-15/16，见 §3.3 与台账 C）；③ 银行流水/转账凭证券类极端密集页 **127.7 s**（2026-09-14，见 §3.5）。①②③ 语料与批次均不同，**不是同一卷内的分位关系** |
| .txt / .md / .docx（整份端到端） | 小件 | **10–12 s** | 含上传→解析→识别→确认→导出→复扫，见 §3.4 |

> [!warning] 文本型 PDF 的覆盖上限（必须与上表同时引用）
> `MAX_HAS_CHUNKS = 12` 使 78 页卷只处理开头约 19,200 字（≈全文 **42%**），超出部分不进入识别。上表「32.4 s」是这一覆盖范围内的耗时，**不能理解为「78 页全量识别只要 32 秒」**。解除该上限的改造见 Issue #115（用文本层+文档级分块替代 12 块硬帽）。

> 历史口径对照（「每页约 30–40 秒」的出处）：2026-09 生产台账 759 页真实案卷、旧栈串行逐页耗时 **中位 34.6 s**、均值 78.5 s、p90 209 s、max 619.8 s。这是早期经验值，**不是**当前 DCU 实例的承诺值；当前口径见本节上表与 §3.3。

### 3.2 单页阶段分解（扫描型，跨卷均值）

| 阶段 | 均值 | 占阶段合计 |
|---|---|---|
| OCR（PP-StructureV3） | 4.21 s | 5.9% |
| **HaS 文本 NER** | **67.52 s** | **94.1%** |
| 阶段合计（两项之和） | 71.73 s | 100% |
| `ocr_has` 阶段计时（含 0.32 s 未细分残差） | 72.05 s | — |
| 视觉特征（LocateAnything-3B，独立阶段） | 6.29 s | — |

> 口径：OCR 与 HaS 是 `ocr_has` 内的**嵌套计时**。三项均值按日志取整后并不严格闭合（`72.05 − 4.21 = 67.84 ≠ 67.52`，残差 **0.32 s** 未细分），故**百分比以阶段合计 71.73 s 为分母**，不要把 67.52 s 当作 `ocr_has − OCR` 的精确值。

**瓶颈定位明确：LLM 实体识别占单页成本的 94%，OCR 只占 6%。** 每页 HaS 调用次数中位 6、均值 23.6、p90 67，其中 **99% 是「逐新值自证」校验**；单次调用延迟中位 462 ms、均值 3,051 ms、p90 4.6 s、max 98.9 s（长生成尾部很重）。因此提速的靶子在**减少 HaS 调用轮次**，不在 OCR。

### 3.3 整卷耗时与页间并发收益

| 场景 | 改动前 | 改动后 | 收益 |
|---|---|---|---|
| 67 页扫描证据卷（页并发 k=1→3，闸门 4→8） | 1,442.0 s（24 分 02 秒） | **485.0 s（8 分 05 秒）** | **2.97×** |
| 10 页扫描件 canary（真实前端代码路径） | 198.13 s | **86.74 s** | 2.28× |
| 3 页扫描件 | 61.93 s | 27.42 s | 2.26× |

页延分布（67 页卷，**k=3 并发下的页墙钟**）：均值 **21.5 s**、p50 19.3 s、p90 30.1 s、max 93.6 s——一页含 **约 130 个候选框**的金融票据密集页需 **86–93 s**（这是本条 67 页证据卷内的取值，落点见台账 C 的「密集页取值」；跨卷极端密集页为 **127.7 s**，见 §3.1/§3.5）。

> [!warning] §3.3 与 §3.2 的数字**不可直接相减**（口径不同）
> §3.2 的 72.05 s 是 **759 页真实案卷生产台账**的 `ocr_has` 阶段**均值**；§3.3 的 p50 19.3 s 是**另一条 67 页证据卷**在 k=3 并发下的**页墙钟中位**。语料、时点、统计量三者都不同，二者不是同一口径。
> 本节的正确读法是：该 67 页卷三臂的单页 reported 成本为 **21.5 / 22.4 / 21.6 s/页**（三臂均值 **21.8 s/页**，改动前后同量级），收益**全部来自页间重叠**——即并发缩短的是整卷墙钟，不是单页成本。

| docx（Word） | 10.43 s | 11.83 s |

### 3.5 吞吐与规模化（云实例）

| 指标 | 实测 | 口径 |
|---|---|---|
| 端到端吞吐（合成样张卷） | **3.9–4.6 页/分钟** | 含 UI 全链路，**两次独立运行**（2026-09-14，构建 `705870d`，早于 §3.1–§3.3）：r3 = p50 **13.9 s** / p95 **15.2 s** / 3.9 页/分钟；v4-demo2 = p50 **13.1 s** / p95 **13.1 s** / 4.6 页/分钟。**分母口径**：页/分钟按**整轮端到端墙钟**（含非识别开销）计，p50/p95 只描述识别页，故 60÷3.9 = 15.4 s/页 会**高于**识别页 p95 15.2 s——两者分母不同，**不可互相反算** |
| 端到端吞吐（真实案卷卷宗） | **31.83 s/页（1.88 页/分钟，对外约 1.9）** | 2026-09-14 真实案卷 e2e（`705870d`）：35 稳态页合计 **1,114.24 s** → **31.83 s/页** → 1.88 页/分钟，故 20 页卷宗约 **10.6–11 分钟**；剔除最密集票据卷（4 页 682.322 s）与加密补充件（1 页 0.032 s）后 **30 页 / 431.886 s → 14.40 s/页 ≈ 4.2 页/分钟**——重尾分布，均值不可当典型值 |
| 单页耗时区间（真实扫描卷） | 6.7–18.0 s；**最慢页 127.7 s** | 同一批 2026-09-14 真实卷 e2e 的逐文件 p50（最小 6.716 s / 最大常态 18.033 s）；127.7 s 为银行流水/转账凭证券（表格密集），是下一个优化靶子 |

> **真实数据税**：合成样张约 13 秒级（p50），真实扫描件按卷差异极大——剔除最密集票据卷后单页约 **14 s**，但含密集票据卷的全卷均值约 **32 s/页**、卷宗吞吐 **1.9 页/分钟**。差额来自噪声、盖章与票据。对外按真实案卷口径报工时（§3.3 逐页口径），不要用合成样张的 3.9–4.6 页/分钟。
>
> §3.5 **只收录本 PR 可核验的云 DCU 实测口径**。v1.0.0 期的生产规模读数（6,720 份万级批量、120,000 行库表导出 4.3 s）属 §4「规模化能力」，其证据与出处见 §4，不在本章性能测量之内，故不列入上表。

**结论：当前单机 DCU 实例的稳态吞吐是「页/分钟」个位数量级（真实案卷 1.9 页/分钟），不存在「几十份文件/分钟」的交付能力。** 对外一律以「页」为单位报工时，并按页密度上浮。

## 4. 规模化能力（万级实测）

- **万级批量**：单任务 10,000+ 文件支持；6,720 份实测批量（生产客户场景）全流程通过
- **批量一键确认**：万级任务后台批量事务处理，接口秒回，进度实时可见
- **异步分卷导出**：导出大小预估秒回（误差 <1%，实测 0.1%）；每卷 ≤2GB 自动分卷；断点续传下载
- **十万行库表**：120,000 行导出实测 4.3 秒、内存峰值 80MB、xlsx 自动按 5 万行分卷（Excel 秒开）
- **上传弹性**：4 路并发上传；大文件分块断点续传；断网后一键重试，幂等保证绝不重复入库

## 5. 安全与合规

- **认证与会话**：JWT + httpOnly Cookie，登录限速与锁定，令牌吊销与全设备下线
- **角色矩阵**：管理员 / 审核员 / 操作员（不可确认审核）/ 只读，服务端统一强制；批量确认为逐人授权的独立权限
- **审计日志**：上传/确认/导出等敏感操作全量留痕，管理员可按人/动作/关键字检索并一键导出 CSV
- **文件安全**：magic bytes 校验防伪造扩展名、病毒扫描、路径穿越防护、租户隔离（用户仅见自己的文件与任务）
- **传输与存储**：本地部署数据不出域；上传原件与匿名化成品目录分离，支持独立备份策略

## 6. 数据库与部署形态说明（选型口径）

平台元数据默认采用嵌入式存储引擎（WAL 模式），与单机本地化交付形态匹配：零数据库运维、开箱即用，实测支撑万级任务与十万行导出无瓶颈。产品路线图包含数据层抽象与 PostgreSQL / 达梦 / openGauss 适配选项，供客户 IT 规范或信创环境要求时启用。库表处理模块已支持直连客户侧 PostgreSQL / MySQL 等主流数据库读取源数据。

## 7. 企业集成能力（第二轮新增）

- **成品水印**：图像/PDF 输出可选平铺半透明文案（如「仅供XX项目使用」），中文渲染内置字体不依赖服务器字体；多页 TIFF 逐帧保留；单文件与批量均可配置，留空即关闭
- **任务完成通知**：批量识别完成/批量确认落定即时提醒；页签在后台时发送系统通知，长任务无需盯屏
- **离线 License 授权**：Ed25519 签名证书（客户名/到期日/席位数/行业包），启动校验+每日复检+文件热更新；到期进入只读宽限期而非硬停机（客户数据永不被锁死）；管理员可在界面内上传续期证书，全程离线
- **LDAP / AD 对接**：企业目录统一认证（直绑/搜索绑定双模式、组→角色映射、TLS 强制）；管理员本地 break-glass 通道保证目录故障时可登录；默认关闭，环境变量启用
- **白标交付**：产品名/标语/Logo/主色四个构建参数整站换牌，交付客户品牌版本无需改源码

以上能力默认关闭（水印/通知除外），存量部署行为零变化；启用均为配置级操作。

## 8. 运维与数据安全（第三轮新增）

- **备份与恢复**：全量例行热备（4 个数据库 + 全部配置与密钥材料，每小时，保留可配）；文件树（原件/成品）走独立增量备份脚本（rsync 硬链，磁盘水位闸）；操作员恢复 CLI 带完整性预检、活服务拒绝与 pre-restore 兜底；备份新鲜度上报健康面板（超期告警）。运维手册：backend/docs/backup-restore.md
- **回收站**：删除默认进回收站（保留 7 天可配），可还原/彻底删除，超期自动清理；软删/还原/清除全部审计留痕
- **账号治理**：管理员可禁用/启用账号（含护栏：不可禁自己与最后一个管理员），禁用即刻生效（在有效期内的登录态一并失效）；密码强度四要素强制
- **API 密钥**：机器对接（M2M）凭据，哈希存储、只读/读写权限域、过期与吊销、最后使用追踪；服务主体全程审计
- **限流与日志**：上传/导出按用户限流（默认宽松不影响万级批量）；审计日志自动轮转（50MB×10）；登录限速与锁定沿用
- **故障自愈**（既有能力）：进程重启自动重排队在途任务；30 秒僵死看门狗；数据库损坏启动时自动从备份恢复

### 9.2 方法

- 处理速度：云实例逐页 `duration_ms` 埋点（OCR / HaS NER / 视觉特征 / 渲染分段）+ 真实案卷整卷实测

- 吞吐：§3.5 的真实案卷与合成样张卷分别由 **e2e 计时装置**取得（逐页 `duration_ms` + 页墙钟 p50/p95 + 页/分钟）。公仓可跑的公开入口：`eval/scripts/run_eval.py`（manifest 驱动的效果+速度评测，口径见 `eval/README.md`）与 `e2e/concurrent_users.py`（并发压测）；**#106 门④ 的逐页计时装置不在公仓**，归档在私有仓 `LexMask-workspace/scripts/issue106-d3/`（`run_d3_final.sh` 等）。`backend/scripts/eval/benchmark_throughput.py`（混合语料 `files_per_min`）为**历史口径，其读数不作为对外承诺，v1.1 起停用**
- 质量：`e2e/industry_recall.py` + `e2e/corpus/{legal,medical,finance}/`（黄金语料+逐项真值）
- 功能：7 条端到端自动化路径（真实 Chrome 驱动生产界面：单文件/批量五步/库表全链路/异步导出/权限矩阵/改密/全路由冒烟）
