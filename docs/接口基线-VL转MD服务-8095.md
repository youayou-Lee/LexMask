# 接口基线：VL 转 MD 服务（vl_md_server，端口 8095）

> 对应 Issue：#40（云实例 DCU 适配 PaddleOCR-VL 1.6，#39 POC 的 T1）
> 服务位置：SCNet 云实例（DCU/DTK），代码 `vl_md_server.py`；部署实录与实例拓扑见私有仓 `LexMask-workspace/docs/deploy/PaddleOCR-VL-1.6-云实例部署实录.md`（git-crypt）。
> 本文档是 **#39 云端链路（NER→替换→兜底→实体 diff）的接口基线**：调用方按此对接，schema 变更须同步更新本文并走评审。

## 1. 服务概要

| 项 | 值 |
|---|---|
| 功能 | 扫描页图 / PDF → Markdown（PaddleOCR-VL 1.6 端到端管线，paddle 原生推理，device=dcu:0） |
| 传输 | HTTP（实例内 127.0.0.1:8095，`0.0.0.0` 监听；跨机访问走 SSH 隧道，勿公网暴露） |
| 进程 | tmux 会话 `redaction` 窗口 `vl-md`，由 `start_all_dcu.sh` 第 6/6 步拉起（2026-10-06 固化） |
| 日志 | 实例 `/root/redaction/cloud-deploy/logs/vl-md.log` |

## 2. 接口定义

### GET /health

健康探针。响应 `200`：

```json
{"status": "ok"}
```

服务启动即预热管线（首跑前模型已加载），`/health` 返回 200 即可受理请求。

### POST /parse

请求体 `Content-Type: application/json`，**二选一**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `path` | string | 实例内绝对路径，`.png` 等图片或 `.pdf`；PDF 支持多页（结果按页拼接） |
| `image_b64` | string | 单张图片的 base64（无文件落盘场景用） |

两个都没有 → `400`。

响应 `200`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `markdown` | string | 转换结果；多页输入时各页以空行（`\n\n`）拼接 |
| `elapsed_s` | number | 本次请求总耗时（秒，1 位小数） |

错误响应（`400` / `404` / `500`）：

```json
{"error": "<原因>"}
```

`404` = 路径不存在（仅 `/health`、`/parse` 两个路由）；`500` = 转换异常，`error` 为异常 repr，此时该请求不产生部分结果。

### 调用示例

```bash
# 文件路径方式
curl -s -X POST http://127.0.0.1:8095/parse \
  -H "Content-Type: application/json" \
  -d '{"path": "/abs/path/page.pdf"}'

# base64 方式
curl -s -X POST http://127.0.0.1:8095/parse \
  -H "Content-Type: application/json" \
  -d "{\"image_b64\": \"$(base64 -w0 page.png)\"}"
```

## 3. 行为约定与已知特性

- **单并发**：`HTTPServer` 串行处理，管线级无锁；并发调用方自行排队（#39 链路按顺序处理页即可）。
- **吞吐量级**（300W 功耗帽、未优化基线）：热跑 38–44s/页；**重启/冷启动后首跑约 90s**（含惰性初始化）。350 页级案卷 ≈ 4h，优化另行立项，不在本接口承诺内。
- **输出形态**：Markdown 正文为模型直出，标题/段落/表格结构可辨；实体（人名、证件号、电话、账号、金额、案号）逐字保留——这是 #39「零泄漏不降级」的前提，调用方**不要**对 `markdown` 做有损预处理后再喂 NER。
- 印章/页边批注文字的覆盖情况以 #40 T4 验证与 #39 实测为准，接口本身不做过滤。
