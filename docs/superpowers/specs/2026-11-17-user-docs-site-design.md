# 用户文档中心（/docs）设计 spec

- 日期：2026-11-17
- 分支：`docs/user-docs-site`（基于 origin/preview @ a28b149）
- 状态：待用户审阅
- 背景：此前产品说明一直靠口述解答用户群体问题；功能迭代后无处沉淀、无人可查。建设一套随代码仓演进、登录可见、与产品同域同风格的在线文档站，作为用户群体的统一说明入口。

## 1. 背景与目标

### 问题

- 产品说明（功能操作、脱敏理念、配置、排障）散落在 5 篇零散文档 + 开发者口述中；
- 用户有问题只能问人，开发者被重复问答消耗；
- 功能迭代后文档无人更新，逐渐失真。

### 目标（第一版）

1. 登录 LexMask 后，从侧边栏「文档中心」进入 `/docs`，看到千帆式三栏文档站（左侧导航树 + 右侧正文 + 本页目录）；
2. 现有 5 篇零散文档重组进统一目录树，另新写 3 篇核心内容（产品简介、脱敏理念与能力边界、FAQ 初稿）；
3. 文档内容以 Markdown 存放在仓内 `frontend/src/features/docs-content/`，功能变更时同一个 PR 即可改文档；用户可感知的变化同步加「更新日志」条目。

### 非目标（第一版明确不做，YAGNI）

- 站内搜索框（预留位置，导航 + 浏览器 Ctrl+F 足够）；
- 文档版本切换 / 多语言 / 在线编辑 / PDF 导出 / 评论反馈组件；
- 部署教程、API 接口、DCU/模型栈细节（内容边界只含产品介绍层 + 功能操作层，内部细节不进用户文档）。

## 2. 用户与访问模型

- 目标读者：律师/法务等终端用户（主）；部署/运维、评委/客户为次要读者。
- 访问控制：与 LexMask 主服务同域，`/docs` 路由复用现有登录守卫——未登录访问跳登录页，登录后回跳。文档内容本身不含敏感信息（无真实案卷、无凭据、无内部架构）。
- 内容边界：
  - ✅ 进：产品介绍层（定位/理念/能力边界/性能数字公开口径）、功能操作层（三模式全流程/预览导出/配置管理/FAQ/排障）；
  - ❌ 不进：部署教程、API 接口、供料模式下 Agent 消费侧集成细节、内部技术栈、验收流程。
- 白标：文档站**不随品牌变量换牌**——正文内的品牌名统一写「本产品」（不硬编码具体产品名），客户品牌定制（替换文档站品牌名/Logo）属后续版本。

## 3. 信息架构（目录树）

```
📖 文档中心
├─ 新手必读
│   ├─ 产品简介                [新写] 墨隐是什么、解决什么问题
│   ├─ 快速开始                [重组] ← 用户使用说明.md
│   └─ 脱敏理念与能力边界        [新写] 只脱"是谁"不脱"发生了什么"/支持什么/边界
├─ 操作指南
│   ├─ 单文件处理              [重组] ← 操作手册.md + 用户使用说明.md
│   ├─ 批量处理                [重组] ← 同上
│   ├─ 预览与调整              [新写] 预览页、页格、单页重试、对照视图
│   ├─ 导出与交付              [新写] 打码/化名、ZIP、页账
│   └─ 供料模式（喂 Agent）     [重组] ← 接口基线-喂Agent模式-agentmd.md（用户视角重写）
├─ 配置与管理
│   ├─ 账号与登录              [重组]
│   ├─ 识别项设置              [重组] ← 用户指南/识别项设置与配置清单设置-使用指南.md
│   ├─ 配置清单                [重组] ← 同上
│   └─ 律师场景配置指南         [重组] ← 用户指南/律师场景-账号识别项配置指南.md
├─ 常见问题与排障
│   ├─ 常见问题 FAQ            [新写] 高频问题沉淀（初稿由 AI 拟，用户审）
│   ├─ 识别效果不佳怎么办        [重组] ← 用户指南/排查与日志-使用指南.md（用户版）
│   └─ 遇到报错怎么办           [重组] ← 同上
└─ 更新日志
    └─ 版本更新记录             [新建] 从 CHANGELOG.md 筛用户可感知条目
```

原则：

1. **每篇文档有唯一"家"**——现有 5 篇全部拆并重组，消除双份维护；
2. **重组不是照搬**——技术腔（fail-closed、管线等）改写成律师能懂的话；
3. **更新日志单独成篇**——只收用户可感知的变化（新功能/体验变化/修复的坑），内部重构不进；
4. **文档即代码**——加一篇文档 = 丢一个 .md 文件，导航树构建时自动扫描生成。

## 4. 技术设计

### 4.1 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| Markdown 渲染 | `react-markdown` + `remark-gfm` | 前端生态主流，按需引 |
| 内容存放 | `frontend/src/features/docs-content/<分类>/<slug>.md`（实际口径见 §4.2 实现口径），frontmatter：`title`/`category`/`order`/`updated` | 与代码同仓，PR 可审查 |
| 路由 | `/docs`、`/docs/:slug` | 复用现有路由守卫与登录态 |
| 渲染策略 | 构建期只做静态资源打包（无构建时预渲染）；frontmatter 校验与导航树构建在运行期完成（与 §4.5、§4.2 实现口径一致） | 静态资源 + 文档页懒加载 chunk，秒开；内容不来自用户输入，无 XSS 面 |
| 入口 | 侧边栏新增「文档中心」菜单项 | 已定 |
| 搜索 | 第一版不做，顶栏预留位置 | YAGNI |

### 4.2 数据模型

每篇 md 文件头部 frontmatter：

```yaml
---
title: 快速开始
category: 新手必读
order: 2          # 分类内排序
updated: 2026-11-17
---
```

构建时扫描 `frontend/docs/**/*.md`，按 `category` 分组、`order` 排序，生成导航树 JSON；无 frontmatter 的文件构建报错（fail-closed，防漏配）。

> **实现口径（2026-11-18 Task 8 对齐，落地与上述设想的三处差异）**：
> 1. 内容目录是 `frontend/src/features/docs-content/<分类>/<中文篇名>.md`（随前端源码走 vite `?raw` glob），不是 `frontend/docs/`；
> 2. 「文件 → URL slug」由**注册表** `DOCS_MANIFEST`（`{ file, slug }[]`）显式承载，导航树在**运行期**由「注册表顺序 + frontmatter」构建，不产出构建期 JSON（slug 取自注册表，不从中文文件名推导，URL 保持英文短名）；
> 3. 因此加一篇文档 = 加 md **+ 加一行注册**（数据表，非逻辑代码）；漏登记/文件缺失由 `docs-manifest.test.ts` 的「注册表 ↔ 磁盘文件一一对应」用例判红（CI fail-closed），不会出现「有文件但导航里没有」的静默漏配。
>
> frontmatter 校验的 fail-closed 落点同理：`parseDocsFrontmatter` 抛错 ⇒ 文档页显式报错不静默渲染；CI 侧由「全量解析」用例判红——**判红发生在 vitest 而非 `vite build`**（build 只读原文、不解析 frontmatter，属已知口径，见 AC5）。

### 4.3 路由与守卫

- `/docs` → 文档站首页（重定向到第一篇「产品简介」或带欢迎页）；
- `/docs/:slug` → 对应文档；未知 slug 重定向回 `/docs`（不渲染空正文）；
- 未登录访问 → 现有登录守卫拦截 → 登录后回跳；
- 侧边栏「文档中心」仅在登录态显示；
- 锚点约定：文档标题（h2/h3）**在单篇内需唯一**，本页目录锚点按标题文本生成（同名标题的锚点会指向第一个，故写作时避免同篇重名）。

### 4.4 页面布局（千帆式三栏）

```
┌──────────────────────────────────────────────┐
│ 顶栏：← 返回产品 │ 文档中心      [搜索预留]    │
├──────────────┬───────────────────────────────┤
│ 左：导航树     │ 右：正文                       │
│ (可折叠,      │  面包屑：文档中心 > 分类 > 标题   │
│  当前页高亮)   │  右上：本页目录锚点             │
│              │  底部：上一篇 / 下一篇           │
└──────────────┴───────────────────────────────┘
```

- 窄屏（<1024px）导航树折叠为抽屉；
- 与产品现有视觉风格一致（沿用现有主题色/字体/间距 token）。

> 实现口径（2026-11-18 门⑥ M-3 注记）：本节示意图中的「顶栏：← 返回产品 │ 文档中心 [搜索预留]」未按图实现——独立顶栏省略，返回靠应用全局侧栏（文档中心入口常驻），搜索预留位不做（同 §2 第一版不做搜索）。其余布局（三栏/面包屑/本页目录/上下篇/窄屏抽屉）与图一致。

### 4.5 渲染管线

1. 构建期：扫描 md（vite `?raw` glob 读原文）；frontmatter 校验与导航树构建在运行期完成（见 §4.2 实现口径）；
2. 运行期：纯静态消费，无用户输入 → 无 XSS 面；
3. 更新：改 md → PR → CI（vitest/tsc/build）→ 合入 preview → 随版本部署。

## 5. 工程流程

- 文档变更与功能变更同 PR 提交（`docs/` 前缀分支，如 `docs/user-docs-site`）；
- 用户可感知变化 → 同 PR 更新日志加条目；
- CI 覆盖：frontmatter 校验用例 + build 必须过 + 无坏链（每篇 md 必须能被扫到）；
- 不需要 GPU 云验收（纯前端内容）；走 Issue 立项 + PR + 门⑥ 评审。

| 篇目 | 来源 | 动作 |
|---|---|---|
| 产品简介 | — | 新写 |
| 快速开始 | 用户使用说明.md | 重组 |
| 脱敏理念与能力边界 | — | 新写（初稿 AI 拟） |

约 15 篇。迁移完成后删除/归档被重组的旧文档（主仓 docs/ 下），避免双份维护。

## 7. 验收标准

- AC1：登录后侧边栏出现「文档中心」，点击进入 `/docs`，看到完整目录树（≥4 分类、全部首批篇目可点）；
- AC2：未登录直接访问 `/docs/xxx` → 跳登录页 → 登录后回到该文档；
- AC3：每篇文档有面包屑、本页目录锚点、上一篇/下一篇；链接零死链；
- AC4：目录树与 md 文件一一对应——加一篇 md（带 frontmatter）**并在 `DOCS_MANIFEST` 登记一行**后，导航自动出现该篇，无需改渲染/路由代码；漏登记或文件缺失由「注册表 ↔ 磁盘文件一一对应」守卫用例判红（2026-11-18 对齐，见 §4.2 实现口径）；
- AC5：frontmatter 缺失/非法的 md 判红（fail-closed）——文档页显式报错、不静默渲染，且 CI 的「全量解析」用例失败；判红落点是 **vitest 而非 `vite build`**（build 不解析 frontmatter，2026-11-18 对齐，见 §4.2 实现口径）；
- AC6：现有 5 篇文档内容全部有唯一归属，无遗漏、无双份；
- AC7：CI 全绿（含新增用例）；`/docs` 在窄屏可用（抽屉导航）；
- AC8：更新日志条目与 CHANGELOG 用户可感知条目对得上。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 重组过程中内容失真（技术文档改写用户语言） | 每篇重组稿用户抽检；FAQ 初稿用户逐条审 |
| 文档与功能漂移（改了功能没改文档） | 流程约束（同 PR）+ 更新日志机制；长期可加 CI 检查（第二版） |
| 前端集成影响现有构建 | 文档路由独立懒加载 chunk，主包体积增量 < 50KB |
| 搜索缺失影响可用性 | 预留位置；导航树条目级锚点 + Ctrl+F 兜底 |
