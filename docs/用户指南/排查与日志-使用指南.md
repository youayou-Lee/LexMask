# 排查与日志 · 使用指南：某一页「发生了什么」怎么看

> **这份指南解决一个问题：识别结果不理想（某页漏了、慢了、失败了）时，怎么查清那一页到底经历了什么。**
> 面向所有用户：前两节人人可看（点页面就能看）；后两节是给管理员/技术支持看的，普通用户可以忽略。
> 适用于 2026-11 起（含「页级事件日志」功能）的版本。

---

## 一、看某一页：点开页格的「第 N 页发生了什么」

批量任务的文件行下方有**逐页格子**（绿=成功、红=失败、灰=未跑）。**点任意一个格子**，会展开这一页的详情面板「**第 N 页发生了什么**」，内容包括：

| 面板内容 | 人话解释 |
|---|---|
| **路由** | 这页走的是「文本层链接管」还是「逐页识别」——前者是系统直接读 PDF 里内嵌的文字（快），后者是逐页当图片扫描识别（慢一点，但结果一样可靠） |
| **总耗时 / 各阶段耗时** | 这页花了多久、时间花在哪（OCR / NER 等各阶段分别多少毫秒） |
| **异常类型** | 如果这页失败，失败在哪个环节、什么类型的错误 |
| **重试次数** | 这页有没有重试过、重试了几次 |

**用法**：发现某页结果不对 → 点开那页的格子 → 先看「路由」确认它走了哪条路，再看「异常类型」和「重试次数」判断是没跑完、跑失败，还是识别本身拿不准。把面板截图发给技术支持，比口头描述「第 37 页不对」快得多。

## 二、看整个卷：文件行顶部的路由标签

每个文件行顶部会有一个小标签，说明这个卷整体走了哪条识别路线：

| 标签 | 含义 | 需要担心吗 |
|---|---|---|
| **文本层链已接管** | 这个 PDF 自带可读文字层，系统直接用它识别——速度快 | 不用，这是最优路径 |
| **文本层链未接管（原因）·走逐页识别** | 系统试过用内嵌文字，但被某个检查拦下了，改用逐页扫描识别 | 不用——逐页线照样完整出结果，只是慢一些 |

「未接管」括号里的常见原因对照：

| 显示的原因 | 人话 |
|---|---|
| 水印命中 | 页面上有水印文字，直接读文字层会把水印当正文，所以改走逐页扫描（更干净） |
| 无内嵌文本层 | 这个 PDF 本质是图片（扫描件），没有可读文字层，只能逐页 OCR |
| 建流超预算 | 文字层太大/太复杂，组装超过了时限，不值得继续等 |
| 文本层质量不合格 | 文字层能读但内容太乱（乱码比例高等），直接用会漏识别 |
| 重复片段覆盖越界 | 文字层里有大量重复文字（常见于水印铺满的卷），系统拒绝把它当正文 |

其余更少见的原因会以英文代码显示（如 `failed_chunks`、`map_failure_ratio`、`block_errors`、`truncated_chunks`、`coverage`），不影响使用——出现时截图问技术支持即可。

## 三、日志存在哪里、里面有什么（概念）

- 系统为每个任务自动记一份**逐页事件流水**（每卷一个文件，记录「哪一页、走了哪条路、每步花了多久、失败在哪儿、重试了几次」），放在服务器的数据目录 `logs/<任务号>/` 下；
- **隐私设计**：这份流水**只记过程，不记案卷内容**——文件名、当事人姓名、正文一个字都不会写进去，并且经过专门的审计脚本验证（见下节）；任务删除时流水跟着一起删掉；超过保留期（默认 14 天）的孤儿流水也会被自动清理；
- **导出的成品（打码/替换后的 ZIP）里永远不含这份流水**——它只留在服务器上供排查，不随交付出厂。

## 四、管理员两条命令（技术支持用）

> 普通用户到上一节为止。以下是服务器侧排查示例，`<尖括号>` 为占位符，按实际任务号替换。

```bash
# ① PII 审计：确认某任务的日志里没有任何身份证/手机号/银行卡/长中文正文（干净则 exit 0）
docker compose exec backend python scripts/audit_page_event_log.py --self-test /app/data/logs/<任务号>

# ② 一条命令复算该任务的过程汇总（页数分布/最慢页/失败页清单，与落盘的 summary.json 核对）
docker compose exec backend python scripts/summarize_job_log.py /app/data/logs/<任务号>

# ③ 看某卷的路由判定链（哪道检查、放行还是回落，附当时生效的阈值快照）
docker compose exec backend cat /app/data/logs/<任务号>/<卷ID>.jsonl \
  | jq -c 'select(.event=="route_decided") | {gate, verdict}'
```

出现识别质量或性能问题时，把 ①② 的输出与出问题那卷的 `.jsonl` 一起打包发给开发，即可还原当时的完整处理过程。
