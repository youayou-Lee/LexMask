## 0. 问题与定调

评测模块的真实案卷私有子集目前只评速度与稳健性，**真实分布上的 P/R 是盲区**；历史证明真问题（人名漏检、表格难例、跨行机构名）全部出自真实案卷。本 Issue 建设「真实效果 GT」的生产管线，试点 100 页走通全流程；扩量由用户看试点数据拍板，不预设。

用户定调（2026-10-06 brainstorm，七节逐节确认）：
- **双 AI 互验预标 + 用户抽检 10%**；兜底通道不预先叠加，看试点效果再定（用户明确：不看效果一昧叠加兜底没意义）；
- 预标通道 = 云 API Paddle VL 双模型（PP-OCRv6 × PaddleOCR-VL，上传授权已留档私有仓 Issue#6）+ 本地 vl-md(8095) 仲裁；
- 标注工作台走本地网页方案（用户抽检/裁决体验优先，工具是反复使用的资产）。

## 1. 总体架构与数据流

```
真实案卷原件（用户本地，永不进任何仓）
   │ ① 选卷脚本按矩阵挑 100 页 → 页面副本进本地工作目录（不入库）
   ▼
② 预标引擎（统一接口：云 v6 × 云 VL 并跑，本地 vl-md 8095 仲裁）
   │    归一化（全半角/空白/Markdown 标记）→ 转录层按页型分域互验
   │    → 实体预标（正则定格式类 → NER 定开放类）→ 实体层三通道交叉
   │    → 分歧分级：自动裁决优先，剩余升级人工
   ▼
③ 本地标注工作台：裁决模式（分歧置顶）+ 抽检模式（10%，产出一致集可信率）
   ▼
④ GT 定稿脚本 → GT v1（JSONL）→ 私有仓 git-crypt 目录
   ▼
⑤ run_eval.py --suite real-gt → 首份真实分布成绩单（纯数字）→ 公开仓 eval/reports/
```

**隐私边界（逐层，不新造例外）**：
- 案卷原件与页面副本：只在用户本地与本地工作目录，不进任何 git 仓；
- 云 API 上传：仅限评测预标用途，授权记录在私有仓 Issue#6 文档；
- GT 文件与一切衍生物（抽检记录、工作台导出、中间转录）：私有仓 git-crypt 目录；
- 公开仓：只有 P/R/F1 数字与页 id。

## 2. 选卷矩阵（100 页）

用户本地案卷库 5 个案件全部进池（名册与选样清单在私有仓，公开仓不出现案名）。按**页型**配额分层：

| 页型 | 配额 | 理由 |
|---|---|---|
| 正文页 | 50 | 主分布，出总体 P/R |
| 表格/流水/目录页 | 25 | 历史漏检重灾区（证据卷目录表格、跨行机构名） |
| 印章/手写批注页 | 15 | 专挑，历史难例挂账的正面覆盖 |
| 边界页（空/极少字/加密） | 10 | 稳健性；互验差分探针已证明空页是分歧源 |

规则：大卷只切「首页+中部页」两段（观察同卷质量漂移）；证据形态最杂的光碟目录卷至少 5 页。选卷脚本产出选样清单（卷×页码×页型×入选理由），**用户签字后引擎才开跑**；页型标注由脚本初判 + 用户过目纠正（页型分错则配额名义成立、实际失真，见验收 B）。

## 3. 互验引擎判定逻辑

原则：**机器能定的自动定，拿不准的才升级**；目标是 100 页升级量压到 50-150 条。

### 3.1 归一化（自动消假分歧）
全半角、空白、Markdown 标记（`##`、`<table>` 残留）归一。差分探针实测：正文页双向覆盖差几乎全是格式噪音。

### 3.2 转录层分域比对（按页型换打法）

| 页型 | 比法 | 判定 |
|---|---|---|
| 正文页 | 双向 8 字滑窗覆盖率 | 双向 ≥90% → 一致集；低于 → 升级 |
| 表格页 | 不比字符流（VL 出 HTML table 必炸）；两边各抽实体比集合互含 | 集合一致 → 一致集；缺谁 → 升级 |
| 空白/低密度页 | 单方多字检测 | 默认升级（探针实测 VL 空页吐水印字） |

### 3.3 实体层三通道交叉
1. **正则通道**（身份证/电话/案号/车牌/银行卡）：置信最高，两转录正则命中不一致直接升级；
2. **NER × 双转录**：同一 NER 分别跑 v6/VL 转录，两份实体列表互验（转录差异传导为实体差异，可抓 NER 单边漏）；
3. **类型冲突检测**：同位置同字类型不同（人名 vs 机构名）→ 升级。

### 3.4 仲裁分支表（穷尽，全部可测）

| # | 情形 | 裁决 |
|---|---|---|
| R1 | 两云转录一致，正则/NER 无冲突 | 一致集（默认可信，进抽检池） |
| R2 | 两云一致，但与 NER/正则冲突 | 正则 > NER 多数；仍不明 → 升级 |
| R3 | 两云转录分歧，本地 vl-md 与云 VL 同读数 | 采 VL 读数（v6 单边错/漏） |
| R4 | 两云分歧，本地 vl-md 与云 v6 同读数 | 采 v6 读数（VL 错/幻觉） |
| R5 | 三方各执一词 | **升级人工**（强制演练路径，见验收 G） |
| R6 | 空页/低密度页单方多字 | 不走仲裁，直接升级 |
| R7 | 纯格式差异 | 归一化后一致即自动通过，不占人工 |

### 3.5 分歧分级与自校准
- 工作台分歧置顶、按页分组三键裁决（对/错/漏）；
- 一致集默认可信的前提由分层抽检验证（见验收 A5）：抽检统计「一致集真实可信率」，低于 98% 触发收紧重跑（收紧动作 = 覆盖率阈值 90%→95% 逐档上调，**循环上界 2 轮**，仍不达标升级用户决策——防无限循环）；
- 本地 vl-md 与云 VL 是近源模型，仲裁对「VL 家族共同盲区」无效——该残余风险由抽检盯防（A5 分层含实体类型），不预先叠加第四通道（用户定调：看效果再定）。

## 4. GT 数据模型

一页一 JSONL 记录：

```json
{
  "page_id": "卷A-p007",
  "source": {"case_ref": "名册编号", "file_sha256": "…", "page": 7,
             "carrier": "scanned", "page_type": "table", "segment": "mid"},
  "transcript_gt": {"text": "定稿转录（原件文本面）", "fidelity": "human-reviewed|machine"},
  "entities": [
    {"text": "…", "type": "姓名",
     "span_original": [120, 123], "span_normalized": [98, 101],
     "origin": "regex+ner", "arbitration": "R3",
     "verify": "consistent|arbitrated|user-confirmed|user-corrected", "note": null}
  ],
  "adjudications": [{"models": ["v6", "vl", "vl-md"], "verdict": "…", "at": "2026-10-06"}]
}
```

关键设计决策（独立评审点名的两处高危，写入 schema）：
- **span 参照文本面显式双记**：`span_original`（原件转录面，eval 消费的唯一面）与 `span_normalized`（归一化面，引擎内部比对用），两者往返映射必须有单测（构造归一化前后 offset 漂移样例验证）——否则引擎在归一化面比对、eval 吃原件面，offset 全漂且验收全绿；
- **类型枚举 = eval_ner_quality.py 口径的双向映射**：零未映射、零缺失（单测固定）。

其余：schema 校验器（offset 在界、重叠策略、枚举合法、页 ID 可回溯原件 sha256）；GT 定稿打版本号（v1），eval 配置钉住版本，重跑数字一致；`transcript_gt` 是 #39 VL 链路 MD 对照的金标准，其保真度随抽检一并核对。

## 5. 本地标注工作台

本地网页（localhost），只做两个视图：
1. **裁决模式**：分歧逐条置顶，左页面图+实体高亮、右三方候选读数（v6/VL/本地 vl-md），三键（对/错/漏）推进，支持改判与撤销（审计留痕）；
2. **抽检模式**：从一致集按「页型 × 实体类型 × 管道路径」分层抽样 10%（采样 seed 落盘可复现），同样三键，产出一致集可信率统计；抽检发现错误一律修正并重算，率只决定是否收紧重跑、不豁免修正。

技术形态：Python 后端 + 单页前端，读写工作目录 JSON，不碰任何仓；UI 自测走内置浏览器自动化（含种子数据断言：改判写回后 span/类型/来源标记正确、可信率对种子数据算出已知值、抽检修正闭环可用）。

## 6. 评测接入

`run_eval.py` 新增 `--suite real-gt`：GT 版本路径参数传入，走现有 e2e 层打 backend 公开 API（真实扫描件 e2e 属 GPU 栈，按门禁③在云实例跑），P/R/F1 用 `eval_ner_quality.py` 唯一口径，数字保真一票否决与三闸门照常。一份 GT 服务三件事：现产品真实分布回归基线、#39「零泄漏不降」验收、NER 选型效果对比（数据底座）。成绩单 Obsidian 版式进公开仓，**附质量注记**（一致集可信率、抽检样本构成、已知残留错误计数——纯数字）。

## 8. 验收方案 v2（2026-10-06 独立评审 REVISE 后修订；每条含可失败反事实）

### A. 引擎质量闸（M1 出口，全部在合成集上验证）
- **A1 合成验证指标可证伪**：实体级精确 span+类型的 **P 与 R 分开报**，总体 P、R 均 ≥95%，且**每个在册类型**单独达标（合成集内该类型实体数 <5 则该类型全查）；span 匹配规则 = 精确 offset + 类型一致；合成集构成清单（页型×实体类型×噪声档）随证据留痕——防止「全用干净正文渲染过门槛」或总体均值掩盖稀有类型系统性错。合成验证产物时间戳先于首卷摄入记录（顺序留痕）。
- **A2 分歧检测注入检验**：向合成转录**植入 ≥50 处已知分歧**（字符替换/span 边界漂移/整实体漏/类型标错/空页单方多字），引擎检出率 ≥95%——「分歧 100% 裁决留痕」是引擎自报口径，漏检的分歧永远进不了册，注入检验是唯一能抓「该升级的没升级」的手段。
- **A3 仲裁分支全覆盖**：R1-R7 每个分支至少一条种子用例走通并留痕；R5（三方各执）与「收紧重跑」两条正常流程大概率触发不了的路径，用种子数据**强制演练**各一次——不演练就是死代码。
- **A4 裁决无静默丢弃**：每个检出分歧有裁决记录（模型/依据/终值）；抽样核对无「检出了但没进清单」的条目。

### B. 选卷闸（M2 出口）
- 选样清单覆盖矩阵每格；**实际处理页与清单逐页对账**；页型标注抽 20 页人工复核（脚本初判可错，错则配额失真）；用户签字记录留档。

### C. 工作台闸（M3 出口）
- 内置浏览器自测全过，断言必须含：改判写回后 GT diff 的 span/类型/人工来源标记正确、撤销可用、可信率对种子数据算出已知值、抽检修正闭环；
- 用户走查必含**一次改判 + 一次抽检修正**（不计时限）。

### D. GT 数据闸（M4 出口）
- schema 校验器全过（offset 在界/重叠策略/枚举/页 ID 回溯）；类型口径双向映射零缺口（单测）；span 双面往返映射单测过（漂移样例）；
- **分层抽检规范**：按 页型×实体类型×管道路径 抽 10%（每层最少 3 条，不足该层全查），seed 落盘；一致集可信率 ≥98%，不达标触发收紧（阈值逐档上调，上界 2 轮）后重抽样复核；
- **前 10 页 100% 人工复核**（预热）：缓解合成验证到真实分布的外推风险（真实件有倾斜/印章/手写），结果计入抽检留痕；
- transcript_gt fidelity 抽检（抽检同时核对转录文本与 span，不只核实体）；
- GT v1 版本钉住，重复出数一致。

### E. 评测接入闸（M5 出口）
- 页数对账：成绩单参与页数 = GT 定稿页数 = 100；在册类型 P/R 无空值；
- 三闸门照常可用（--baseline 对比跑一次留痕）；
- 成绩单附质量注记（纯数字）。

### F. 隐私闸（贯穿）
- 公开仓全历史扫描：页面图/实体原文/案件名册/transcript 片段零命中，扫描方法对 GT 工件类补充「JSONL 结构指纹 + 高密度中文文本块检测」；
- 私有仓 GT 及全部衍生物（抽检记录/工作台导出/中间转录）**逐文件核验 git-crypt 属性生效**；.gitattributes 新路径模式先于任何 GT 内容提交；
- 案卷原件不入任何仓（工作目录核验）。

### G. 环境与流程（贯穿）
- 每条验收标注执行环境：M1-M3 纯本地；M4 预标外呼云 API（凭据照私有仓 Issue#6）；M5 e2e 在云实例（门禁③）；
- 云 API 不可用时验收**挂起而非降级放行**；
- 试点复盘汇报后扩量由用户拍板（里程碑声明，不承担抓错责任）。
