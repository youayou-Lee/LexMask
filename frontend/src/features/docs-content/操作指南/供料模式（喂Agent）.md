供料模式解决一个具体问题：怎么把整本案卷安全地交给云端 AI 去做摘要、审阅、要素抽取。

直接上传原件不行——案卷里有当事人姓名、证件号、账号，云端模型不该看到。供料模式先把案卷转成**脱敏 Markdown**，同时生成一份**映射表**，AI 拿到的是干净的文本，您手里留着还原的钥匙。

## 它产出什么

一份 PDF 案卷进去，出来三件东西：

| 产物 | 内容 | 用途 |
|---|---|---|
| 脱敏 MD | 全文 Markdown，敏感实体已替换为占位符（如 `[PERSON_1]`） | 直接投喂给云端 AI |
| 映射表 | 每一处替换的原文、类型、占位符 | 核对、必要时还原 |
| 保留字段清单 | 本次选择保留原文的字段及所在页 | 交给云端侧做审计说明 |

## 入口在哪

左侧导航「**供料模式**」：独立页面，从上传到出稿都在这里完成。

多份文件想走供料时，也可以用批量向导的「供料」通道（见下文「批量供料」）。

## 处理流程

1. **上传 PDF**：一次一份。非 PDF 文件会明确提示不支持；
2. **解析**：系统读取版式、表格与图片，把 PDF 变成结构化文本。大卷这一步最花时间；
3. **实体识别**：找出其中的人名、机构、证件号等敏感信息；
4. **确认映射表**：逐行决定替换什么；
5. **确认生成**：产出三件套，可下载或一键复制。

进度页会显示当前阶段（排队等待解析 / 解析中 / 实体识别中）、总页数与已用时间。解析阶段按单卡串行排队，前面有大任务时需要等一会儿，属于正常现象。

## 映射表怎么确认

每一行是「原文 / 类型 / 将替换为」，三种操作：

- **保留原文**：这一处不替换，会进入保留字段清单；
- **恢复替换**：之前标了保留，改回替换；
- **自定义替换值**：不用默认占位符，填您自己的替换文本。

两点提醒：

- 如果本次**一个敏感实体都没识别到**，系统会给出显式告警，需要勾选「我已知晓」才能继续生成。这是防止把没脱敏的稿子直接送出去；
- 解析过程中如果有个别内容无法提取（例如截图里的文字），会以「解析提示」列出，不影响继续使用，但建议您看一眼再决定是否出稿。

## 大卷要等多久

解析速度大致在每页几秒到几十秒之间，取决于页面密度与表格数量。几百页的案卷通常是小时级。解析阶段没有逐页进度，只显示总页数、阶段与已用时间——这是正常的，不是卡住了。

## 拿到之后怎么用

- **一键复制喂 AI**：把脱敏 MD 复制到剪贴板，直接粘贴给云端模型；
- **下载脱敏 MD**：存档或走内部审批后再外发；
- **下载映射表**：与 MD 分开保管，别一起发给外部；
- **下载保留字段清单**：说明哪些原文没有替换，便于云端侧或合规同事核查。

需要把化名还原成原文时，用下载的映射表在左侧「还原工具」里做一次还原即可。

## 批量供料

一次要处理很多份时，用批量向导的供料通道：支持 PDF、Word、文本与扫描件，逐份转成脱敏 Markdown，确认映射表后整批导出，附还原用的映射表。

## 边界与安全

- 单文件供料目前**只支持 PDF**；Word 与文本请走批量供料通道；
- 加密 PDF 需要提供打开密码，密码只用于本次解密；
- 服务重启（如升级维护）时，仍在解析中的任务会被标记为已中断，需要重新发起；已经完成映射确认的任务可以继续复核与出稿；
- 脱敏 MD 与映射表的安全级别与原件相同，请按内部规定保管与外发；
- 交给云端 AI 之前，请确认所用的模型服务符合您所在机构的数据合规要求。

## 与「打码 / 替换」的区别

| | 打码 / 替换 | 供料模式 |
|---|---|---|
| 产物 | 版式化的 PDF、Word、图片 | Markdown 文本 + 映射表 |
| 适合 | 交给法院、客户、对方律师 | 交给云端 AI 做文本处理 |
| 可读性 | 保持原版式 | 纯文本，便于模型消费 |

两者用的是同一套识别能力，区别只在产物形态。同一份案卷可以两种都出：对外给版式化的成品，对内做 AI 处理用供料稿。
