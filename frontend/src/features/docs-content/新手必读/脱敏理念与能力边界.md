在用之前，先花三分钟了解这套系统「会做什么、不会做什么」。清楚边界，比记住按钮在哪更重要。

## 一条主线：脱「是谁」，不脱「发生了什么」

法律文书的价值在于事实。如果把案情、时间、金额、争议焦点一起打掉，文件就失去了可用性。本产品的默认口径是：

- **要脱敏的**：能定位到具体个人或主体的信息——姓名、身份证号、手机号、家庭住址、银行账号、出生日期等；
- **要保留的**：案件事实、事件经过、法律程序信息——立案日期、开庭时间、案由、合同条款、裁判理由等。

单次处理默认查「法律卷宗」组合（11 类），不含车牌、邮箱、机构名和事件日期；需要这些类型时，在上传区的识别范围里选「全部类型」或自定义清单。

所以当您看到「立案日期」这类信息没被打码，那不是漏了，而是刻意的：它属于「发生了什么」，脱了就没人看得懂了。请注意「出生日期」与「事件日期」是两个独立识别项——出生日期默认在查、会打码；事件日期默认不打，需要时可以在「高级设置 → 识别项设置」里调整。

## 两种处理方式，对应两种用途

| 方式 | 成品长什么样 | 适合 |
|---|---|---|
| 打码 | 敏感内容被直接遮盖，版式与原件一致 | 存档、机器处理、不需要再读那部分内容的场景 |
| 替换（化名） | 敏感内容换成同类虚构词，文档仍然可读 | 给领导、客户、对方律师看的汇报版卷宗 |

打码在**批量处理**里可选三种文本呈现形式（清晰标签 `<姓名[001]>`、自然替换 `[姓名一]`、直接掩码 `陈**`）；单次处理的打码就是直接遮盖，没有子选项。图像类打码（批量）还支持马赛克 / 模糊 / 纯色遮挡与遮挡强度、颜色设置。

成品本身不含还原入口：供料模式的产物附映射表 JSON，可以在还原工具中还原出原文；打码与化名替换的成品没有还原入口（化名对照表只供人工核对）。

## 系统保证什么

- **同一原文全文同名**：同一个人或机构在全文所有位置替换成同一个化名；
- **不同原文不共用**：默认口径下两个人不会共用一个化名，各自独立编号（词库若配置为循环复用策略则不保证）；
- **所见即所打**：打码成品按您在预览中勾选的框遮盖；
- **交付口径可选**：部分 PDF 自带的水印层可选择「保留」或「成品不带原水印」（默认保留）；
- **不会悄悄降低处理标准**：识别失败的页会被显式列出，不会当作「干净页」混进成品；
- **数据不出域**：识别与处理全部在您的部署环境内完成。

## 系统不保证什么

这部分请务必知悉，它决定了您的复核力度：

- **不保证零漏检**：机器识别有概率漏掉某些形态（例如排版特殊、断行、夹空格的内容）。**人工复核与成品抽查是流程的一部分，不是可选项**；
- **不保证版式完全一致**：文本型 PDF 的替换成品经 Word 中转重新排版，版式可能与原件有细微差异。对版式一致性要求高的场景请改用打码；
- **不保证跨文件化名一致**：化名一致性只在单个文件内成立。不同文件里同一个人可能是不同化名，这是预期行为；
- **不提供法律意见**：系统只负责按您设定的口径识别与遮盖，脱敏范围是否充分由您判断。

## 支持范围与已知限制

| 限制 | 说明 |
|---|---|
| 打码仅对 PDF / 图片开放 | Word 与纯文本文件请用替换 |
| 扫描型 PDF / 图片不支持替换 | 这类文件只能用打码 |
| 批量处理不支持替换（化名） | 多文件批量打码可用；化名需求请逐份走单次处理 |
| 纯文本与 Word 无「页面视图」 | 只有文本对照视图，标注在文字上进行 |
| 加密 PDF 需要密码 | 上传时会提示输入打开密码，密码仅用于本次解密，不会被保存 |
| .rtf 不予受理 | 解析会破坏中文编码，上传会被直接拒绝 |

## 一个建议的工作习惯

1. 先拿一份文件小范围试处理，确认识别口径；
2. 复核时不要只看「有没有打」，也要看「是不是打得过多」——把不该打的（如案号、合同条款）取消勾选；
3. 成品下载后抽查一遍，尤其是表格、跨行、扫描件；
4. 化名对照表与原件同等保管，**不要随成品一起外发**。

## 出了问题怎么办

先不要重跑整批。先看《预览与调整》确认是识别问题还是复核操作问题，再看《常见问题》。涉及某几页反复失败的，可以单独重试那几页，不必重跑整卷。
