报错分三类：**上传被拒**、**识别 / 处理失败**、**导出失败**。大多数报错都带着原因和下一步怎么做，按提示走一遍通常就解决了。这一篇按阶段整理。

先说三条通用原则：

1. **不要连续点。** 报错之后连点提交，只会排出更多重复任务；
2. **先刷新一次。** 任务状态显示滞后很常见，刷新后页面会对上真实进度；
3. **记下页号、时间和提示原文。** 找管理员时，这些比「又报错了」有用一百倍。

## 上传阶段的报错

### 提示格式不支持

系统支持的格式：Word（.doc / .docx）、纯文本（.txt / .md / .html / .htm）、PDF（文本型与扫描型）、常见图片（.jpg / .jpeg / .png / .bmp / .gif / .webp / .tif / .tiff）。

- **.rtf 请勿使用**：实测脱敏不彻底，成品可能残留敏感信息，不要拿它处理正式业务；
- **.doc 可以传**：成品会输出为 .docx，版式可能与原件有细微差异；
- 文件大小默认不限；如果部署方设置了上限，超限时会明确提示。

### 提示「文件内容与扩展名不符」

文件改名不会改变它的真实格式。比如把一个图片文件改名成 `.pdf`，系统会检测出真实格式并告诉您，请按提示改成正确的扩展名，或换一份真正的 PDF。

### 上传到一半断了

网络恢复后，在错误卡片上点「重试失败文件」即可续传，不必从头再来。批量上传支持断点续传。

### 提示需要密码

加密 PDF 需要输入打开密码才能处理。密码只用于本次解密，不会被保存。忘记密码只能找文件的提供方。

## 识别阶段的报错

### 提示服务不可用 / 无法提交识别

文字识别（OCR）和语义识别是必需服务。它们不可用时，系统会拦住识别并提示联系管理员——这是故意的，缺了它们根本跑不出结果，与其跑一半失败，不如一开始就说清楚。

请把提示原文和发生时间告诉管理员。同时可以看一眼页面左下角的服务状态，如果显示异常，多半是服务没起来或在重启。

### 印章 / 签名这次没检测

印章、签名检测是可选服务。它没有启动时，系统会跳过这部分并在页面上给出提示，文字识别照常完成。看到这条提示时请知悉：**本次成品里的印章与签名没有做遮盖**，如果这些内容在您的场景里必须处理，请联系管理员把服务启动后重新识别。

### 提交后界面卡住几秒

旧版本在大文件提交时会卡住约 9 秒，看起来像没反应。这个问题已经修复。如果仍然遇到，等两三秒再刷新一次；不要反复点「开始匿名化」。

### 提示「需先完成识别」或「任务已进入终态」

这两个提示通常出现在重试某一页的时候：

- **需先完成识别**：这一页所在的识别还没跑完，等它跑完再重试；
- **任务已进入终态**：任务已经确认结束（或已取消），页不能再单独重试。需要重新处理的话，重新识别整卷或重新上传。

### 提示任务正忙 / 这一页不在可重试范围

同一个任务同时只能有一个识别动作在跑，等当前这轮结束再操作即可。另外，只有识别失败的页才能单独重试——如果这一页其实是成功的，就不会出现在可重试的范围里，这是正常的。

## 打码 / 匿名化阶段的报错

### 按钮是灰的，点不了

两种常见原因：

- **替换（化名）模式下有行没填替换词**——把化名映射表填齐；
- **所有敏感项都被移除了**——点「重新识别」恢复。

按钮下方一般会有对应提示，照着做即可。

### 提示「匿名化失败」

现在这条提示会尽量带上中文原因（任务已取消、状态不符等），并给出下一步怎么做：通常是刷新后重试，或者重新识别一次。如果提示仍然笼统，请把原文截图给管理员。

### 扫描件 / 图片想用「替换（化名）」

不支持，这是能力边界不是故障。这类文件请用打码；换成 Word / 文本型 PDF 才能用化名替换。

### 纯文本 / Word 为什么没有打码选项

打码（遮盖）只对 PDF 与图片开放。Word 与纯文本请用「替换（化名）」，敏感词会换成化名或 `<姓名[001]>` 这样的标签，同样达到脱敏效果。

## 导出阶段的报错

### 导出包里的页比预期的少

先看导出界面的失败页清单，以及（勾选后生成的）包内「说明.txt」。**识别失败的页不会被当作干净页打进包**，这是刻意设计——与其交一份「少了几页」的成品，不如让您知道少了哪几页。

正确做法：回任务详情单独重试那几页，再重新导出。

### 提示分卷

正常。超过 200 份会自动切换为后台分卷导出，每卷不超过 2GB，逐卷下载后合并解压即可。

### 一直排队 / 导出很慢

大批量导出是后台任务，前面有别的导出任务时会排队。可以先做别的，完成后会有提示。长时间无变化时联系管理员。

### 预览结果用不了

识别过程中生成的预览只覆盖已经处理完的那批页。识别收尾后这批预览仍然有效，可以继续查看和下载；但如果任务已经确认结束或被取消，就不能再新生成子集预览了——页面会提示改用整卷入口，按提示走即可。

### 下载失败

先确认网络；分卷的包要全部下载完再解压。仍然失败时把提示原文给管理员——现在的下载错误会给出具体原因，不会再显示成空白的「{}」。

## 报错里的英文

系统会尽量把错误翻成中文。偶尔仍会看到英文代码（如 `item_busy`、`FILE_CONTENT_MISMATCH`）或英文句子，这通常表示遇到了一个比较少见的情况。您不需要理解它，把**原文截图**给管理员即可——这些代码正是用来快速定位的。

## 自助排查的顺序

1. 刷新页面，看提示是否还在；
2. 换一份小文件试一次，判断是「这份文件的问题」还是「整个系统的问题」；
3. 看页面左下角的服务状态与版本号；
4. 仍然不行，联系管理员或技术支持。

## 报问题时给什么

- 账号名、发生时间；
- 文件名与页号；
- **报错提示的原文或截图**（这一项最重要）；
- 页面左下角的版本号。

不要为了报错把原始案卷发到外网。截图与提示原文足够了。
