## 公开数据集接入前核查规程（LEVEN 教训，2026-10-06 立）

背景：LEVEN 曾因轻信文档宣称被选为司法桶主力，实测发现仅有事件触发词标注、无实体标注，两桶 BLOCKED。此后**任何公开数据集接入前必须过以下五步，缺一步不许进适配器**：

1. **许可证核查**：找到数据页/仓库明示的许可证原文（截图或引文留底）；确认允许再分发与我们的使用场景。许可证只在口头/README 一句话提及而无正式条款的，按「未核实」处理。
2. **实测抽查标注**：下载样例文件，脚本统计**实际标注类型与数量**，与文档宣称逐项对照。宣称与实物不符的，以实物为准并记录勘误（LEVEN 教训：论文/README 宣称不可信，实测才算数）。
3. **类型覆盖对照**：实测出的类型清单对照 `backend/config/preset_entity_types.json` 的 preset 类型，逐类给出映射或「丢弃」结论；映射表人工核对后锁版本进 `t2/spec.py`（T2 惯例）。
4. **规模与领域核对**：样本量、平均长度、领域分布（罪名/文书类型）是否满足目标桶定位（能力基线桶 vs 领域差异桶）。
5. **分级结论落盘**：可接入 / 待观察（列明堵在哪一步）/ 证伪（记原因，防止后人重蹈）。候选表提 Issue #51 评论区留痕。

接入约定（沿 #51 正文）：下载脚本入库、数据本体不入库（云 `/root/private_data/benchmarks/` + 本地 `test-data/` 双份）；manifest 记来源 URL + 版本 + 许可证；许可证条款与核查结论登记到本 README 对应条目下。
