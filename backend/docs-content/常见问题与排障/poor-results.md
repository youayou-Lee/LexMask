「效果不佳」通常是三种情况：**该打的没打**、**不该打的打了**、**某一页的结果不对或失败了**。三种的处理方式完全不同，先分清是哪一种，再动手——不要一上来就整卷重跑。

## 先分清是哪一类

| 症状 | 可能的原因 | 先去哪看 |
|---|---|---|
| 某类信息大面积没识别出来 | 这次选的识别项 / 清单不含它，或账号里被停用了 | 右栏识别卡片上的「调整识别项」→ 看本次勾了什么 |
| 个别地方漏了（表格里、跨行、夹空格） | 排版特殊，机器识别有概率漏 | 复核视图手动补框 / 补标注 |
| 不该脱的被脱了（案号、合同条款、事件时间） | 识别项开多了，或本次清单选错了 | 复核时取消勾选；整类问题去「识别项设置」 |
| 某一页结果明显不对、或页格是红的 | 这一页识别失败或走了另一条识别路线 | 批量任务点那一页的格子看详情；单文件看结果页「详情」的失败页清单 |
| 整卷都慢、像卡住了 | 服务排队、文件大、扫描件多 | 看进度页的真实完成数与已用时间 |

## 看某一页到底经历了什么

批量任务的文件行下方有逐页格子：**绿 = 成功、红 = 失败、琥珀 = 人工（人工补框页）、灰 = 未跑**。在批量审阅里点红色的（失败）格子，或带「人工」标记的格子，会展开这一页的详情面板「第 N 页发生了什么」。

| 面板里的内容 | 通俗解释 |
|---|---|
| 识别路线 | 这页走的是「文本层链」（系统直接读 PDF 里内嵌的文字，快）还是「逐页识别」（把每页当图片扫描识别，慢一点但结果同样可靠） |
| 总耗时 / 各阶段耗时 | 这页花了多久、时间花在哪（文字识别、语义识别各占多少） |
| 异常类型 | 如果失败，是卡在哪个环节、什么类型的错误 |
| 重试次数 | 这页有没有重试过、重试了几次 |

**点格子只看原因，不会触发重试。** 「看原因」和「重试」是两个动作：确认原因后，在详情面板里点「重试这一页」（识别没跑完、或上一轮重试还没结束时，这个按钮不可用；任务已经确认结束后也不可用）。

成功页（绿格）在批量审阅里点只会选中它，不展开详情——这是有意的：审阅时不需要每页都看技术信息。要看成功页的耗时和阶段信息，去结果页的「详情」弹窗。

发现某页结果不对时，先看「识别路线」——路线不同，排查方向也不同。然后把面板截图发给技术支持，比口头描述「第 37 页不对」快得多。

### 单文件怎么处理

单文件处理页没有页格详情：那里的逐页格只用于选页导出，点页码不会展开技术面板。要看这一份文件哪里出了问题，用结果页右上角的「详情」：里面能看到总耗时、各阶段耗时和**失败页清单**；失败页在导出界面里也会单独列出。

## 看整卷走了哪条识别路线

每个文件行的顶部有一个小标签，说明这一卷整体走了哪条识别路线：

| 标签 | 含义 | 需要担心吗 |
|---|---|---|
| 文本层链已接管 | 这个 PDF 自带可读文字层，系统直接用它识别——速度快 | 不用，这是最优路径 |
| 文本层链未接管（原因）· 走逐页识别 | 系统试过用内嵌文字，但被某个检查拦下了，改用逐页扫描识别 | 不用——逐页识别照样完整出结果，只是慢一些 |

「未接管」括号里的常见原因：

| 显示的原因 | 人话 |
|---|---|
| 水印命中 | 页面上有水印文字，直接读文字层会把水印当正文，所以改走逐页扫描（更干净） |
| 无内嵌文本层 | 这个 PDF 本质是图片（扫描件），没有可读文字层，只能逐页识别 |
| 建流超预算 | 文字层太大 / 太复杂，组装超过了时限，不值得继续等 |
| 文本层质量不合格 | 文字层能读但内容太乱（乱码比例高等），直接用会漏识别 |
| 重复片段覆盖越界 | 文字层里有大量重复文字（常见于水印铺满的卷），系统拒绝把它当正文 |

少数更少见的原因会以英文代码显示（如 `failed_chunks`、`coverage`），不影响使用——出现时截图问技术支持即可。

## 按症状对照处理

### 漏打与多打

这两类的具体处理（手动补框 / 取消勾选 / 整类关掉识别项 / 调整识别项后重新识别），《常见问题》的「识别结果不对」一节已经写全了，这里不重复。排障时只需要先分清一件事：**是「这一次选错了范围」，还是「账号里本来就不该查这一类」**——前者用识别卡片上的「调整识别项」重跑一次；后者去「高级设置 → 识别项设置」改开关，改完对新任务生效，旧任务不会跟着变。

### 某一页总是不对

在批量审阅里点那一页的格子，把「识别路线 / 异常类型 / 重试次数」三项截图。如果这页是红色（失败），可以按提示单独重试；重试只影响这一页，其余页的结果和您已做的复核都保留。单文件请截结果页「详情」里的失败页清单。

如果这一页反复重试都失败，而您又必须交出完整的一份，可以在批量审阅的失败页详情里点「人工补框」，自己拉框补齐后交付——这些页会带上「人工」标记，并在说明文件里写明未经自动识别校验。

### 表格里的内容老是漏

表格是识别的薄弱环节：跨行的内容、单元格里孤立的值、没有上下文提示的出生日期，都可能识别不到。这类内容请把复核重点放在表格页，成品下载后再抽查一遍。供料模式的产物会尽量保留表格结构，但识别效果仍取决于表格本身的清晰度。

## 什么时候该联系技术支持

出现下面这些情况，自己排查通常解决不了，直接找管理员或技术支持：

- 某一页反复重试都失败，页格一直是红的；
- 整卷识别失败，或识别长时间没有进展（进度长时间不动）；
- 明显该识别的内容整类识别不到，换清单、重新识别都无效；
- 页面提示服务不可用、模型离线之类的消息。

报问题时请提供：

1. 账号名与发生时间；
2. 文件名与具体页号（不要只写「第 37 页不对」，要说清是哪份文件的第几页）；
3. 截图：批量任务给页格详情的截图（含「识别路线 / 异常类型 / 重试次数」），单文件给结果页「详情」里失败页清单的截图；
4. 页面左下角的版本号。

**不要把原始案卷文件发到外网或外部群。** 识别与处理都在您的部署环境内完成，排查也不需要原件——截图与页号足够了。

## 关于日志，您可以放心

系统会为每个任务记一份逐页的处理流水（哪一页、走了哪条路、每步花了多久、失败在哪、重试了几次），但：

- **只记过程，不记内容**——文件名、当事人姓名、正文一个字都不会写进去；
- 任务删除时，这份流水跟着一起删除；超期的也会自动清理；
- **导出的成品包里永远不含这份流水**，它只留在服务器上供排查，不会混进最终交付的文件。

这些流水主要给管理员和技术支持用。您日常使用不需要关心它，只要知道「出了问题有据可查」即可。
