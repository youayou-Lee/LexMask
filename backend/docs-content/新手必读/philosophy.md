# 脱敏理念与能力边界

## 一条主线：脱「是谁」，不脱「发生了什么」

法律文书的价值在于事实。本产品的默认口径是：只处理能定位到具体个人或主体的信息（姓名、证件号、手机号、住址、账号、出生日期等），保留案件事实、事件经过与法律程序信息（立案日期、开庭时间、案由、合同条款、裁判理由等）。

所以看到「立案日期」没被打码不是漏了，而是刻意的；「出生日期」与「事件日期」是两个独立识别项，出生日期默认在查、会打码。

## 系统保证什么

同原文全文同名、不同原文不共用（默认口径）、所见即所打、失败页显式列出、数据不出域。

## 系统不保证什么

- **不保证零漏检**：特殊排版、断行、夹空格、手写、图片内文字可能漏掉；人工复核与成品抽查是流程的一部分，不是可选项。
- **不保证版式完全一致**：替换成品经文档中转可能细微重排；版式要求高请用打码。
- **不保证跨文件化名一致**：一致性只在单个文件内成立。
- **不提供法律意见**：脱敏范围是否充分由您判断。

## 当前限制

- 打码仅对 PDF / 图片开放，Word 与纯文本请用替换；
- 扫描件 / 图片不支持替换，只能打码；
- 批量处理暂不支持化名替换，化名请逐份走单次处理；
- 单文件供料仅支持 PDF，Word / 文本请走批量供料；
- 纯文本与 Word 没有页面视图，只有文本对照视图；
- 加密 PDF 需要提供打开密码（仅用于本次解密，不保存）；
- `.rtf` 不予受理。

## 一个建议的工作习惯

先小范围试处理；复核时既看「有没有打」也看「是不是打得过多」；成品下载后抽查表格、跨行、扫描件；化名对照表与原件同等保管，不要随成品外发。
