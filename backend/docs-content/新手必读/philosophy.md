# 脱敏理念与能力边界

## 一条主线：脱「是谁」，不脱「发生了什么」

法律文书的价值在于事实。本产品的默认口径是：只处理能定位到具体个人或主体的信息（姓名、证件号、手机号、住址、账号、出生日期等），保留案件事实、事件经过与法律程序信息（立案日期、开庭时间、案由、合同条款、裁判理由等）。

所以看到「立案日期」没被打码不是漏了，而是刻意的；「出生日期」与「事件日期」是两个独立识别项，出生日期默认在查、会打码。

## 系统保证什么

同原文全文同名、不同原文不共用（默认口径）、所见即所打、失败页显式列出、数据不出域。完整定义见 [[delivery-modes|两种模式]] 与 [[architecture|技术与架构]]。

## 系统不保证什么

不保证零漏检、不保证版式完全一致、不保证跨文件化名一致、不提供法律意见。逐条说明见 [[quality-boundaries|质量与性能边界]]。

## 当前限制

打码仅 PDF/图片、扫描件不可替换、批量不支持化名等，见 [[current-limits|当前能力边界]]。

## 一个建议的工作习惯

先小范围试处理；复核时既看「有没有打」也看「是不是打得过多」；成品下载后抽查表格、跨行、扫描件；化名对照表与原件同等保管，不要随成品外发。
