## 0. 一页纸

**一句话**

> 墨隐把文件里的敏感信息找出来，遮掉或换成化名，输出仍然是你原来的文件格式；同一份文件还可以额外生成一份给 Agent 读的结构化文本。

**三句话**

1. 高敏感文档要用，但不能带着"是谁"的信息出门；
2. 墨隐在本地把"是谁"识别出来、遮掉或换掉，保留"发生了什么"；
3. 一份材料出两种产物：给人用的原格式成品，给 AI 用的结构化供料。

**定位**：全行业、私有化部署的去标识化基础设施。
**当前版本**：v1.0 聚焦法律文书场景；全行业是产品定位，不是当前版本的全部能力。
**主张**：只隐其名，不失其事。
**三条边界**：不承诺匿名化；不承诺零漏检；不承诺版式完全一致。

## 1. 项目是什么

### 1.1 定义

墨隐是一套部署在用户自己服务器或内网中的**文档去标识化工作台**。它处理 Word、PDF（含扫描件）、图片与纯文本，自动识别其中的姓名、证件号、地址、机构、账户、印章等敏感信息；用户逐条复核确认后，把敏感信息**打码**或**替换**，导出可以直接对外使用的成品；对需要交给 AI 处理的场景，还可以输出结构化供料。

原始文件始终留在用户自己的部署环境里，不经过任何第三方服务。这是它与在线脱敏工具最本质的区别。

### 1.2 两种模式

| | 传统模式（原格式成品） | 供料模式 |
|---|---|---|
| 输出 | 可归档、可提交的成品文件（PDF / Word / 图片），该遮的遮、该换的换 | 脱敏 Markdown + 映射表 + 保留字段清单 |
| 给谁 | 法院、客户、对方律师、监管、公众 | 下游 AI 程序 / 大模型 / Agent |
| 还原 | 不提供还原入口（化名对照表仅供人工核对） | 凭映射表可在还原工具中还原 |
| 流程 | 上传 → 识别 → 复核 → 处置 → 导出 | 上传 → 解析 → 识别 → 确认映射 → 生成三件套 |

两种模式用的是**同一套识别能力**，区别只在产物形态。同一份材料可以两种都出。

### 1.3 全行业定位

产品定位是**全行业**：底座与行业无关，识别、复核、处置、交付四层能力不绑定任何行业；行业差异只体现在**识别项组合、处置口径与合规话术**，不在引擎。

**当前版本（v1.0）聚焦法律场景**：法律预设最完整，操作文档与默认流程以法律文书为主。内置四套行业预设：法律（14 类识别项）、医疗（18）、金融（16）、政务（11）；医疗、金融、政务可直接用预设或自定义清单，后续版本逐步补齐行业化能力。

### 1.4 不是什么

- **不是匿名化产品**：映射表可还原，我们做的是去标识化（见 §8.1）。
- **不是云服务 / SaaS**：本地或内网部署，模型与数据都不出域。
- **不是通用大模型的套壳**：模型只负责"找"，改文由确定性规则执行。
- **不是只做法律**：当前版本聚焦法律，但产品定位是全行业；法律只是第一个做深的场景。
- **不是单一打码工具**：可复核、可审计、可批量、可供料。

## 2. 为什么做

### 2.1 合规边界

《个人信息保护法》《数据安全法》《网络数据安全管理条例》已经划出边界：处理个人信息应当遵循最小必要；可以指向某个人的信息，不能想用就用。法律文书、病历、合同、流水恰恰是"有价值且高敏感"的典型。

### 2.2 三种旧做法的代价

| 做法 | 代价 |
|---|---|
| 不共享 | 数据价值归零，业务做不了 |
| 简单抹除 | 材料作废，事实与法律关系一起没了 |
| 人工打码 | 慢、尺度不一、容易漏、难以审计 |

保护与可用，被当成了二选一。脱敏是让两者同时成立的解法——但前提是做得准、做得全、做得可核查。

### 2.3 为什么是现在

AI 与 Agent 要工作，第一步都是拿到材料；而材料不能出门。把高敏感文档变成"AI 可读、又不指向具体人"的数据，是法律 AI 乃至各行业 AI 的第一层基础设施。墨隐把这件事做成可复核的链路，并用供料模式直接对接下游 AI。

## 3. 能力地图

| 层 | 做什么 | 关键点 |
|---|---|---|
| 解析 | PDF / Word / 图片 / 纯文本 → 可处理结构 | 扫描件走 OCR；加密 PDF 需密码；.rtf 拒收 |
| 识别 | 规则 + 语义 + 视觉三路互补 | 67 类实体（9 个信息域）+ 22 类视觉要素；四套行业预设 |
| 复核 | 逐条勾选、补框、撤销、页级对照 | 人确认后才处置；未确认不导出 |
| 处置 | 打码（遮盖 / 马赛克 / 模糊 / 纯色）或替换（化名 / 占位符 / 掩码） | 同原文全文同名；不同原文不共用（默认口径） |
| 交付 | 原格式成品 / 供料三件套 / ZIP 分卷 | 失败页不进包；成品可抽查 |
| 审计 | 映射表、保留清单、页账、操作日志 | 每页成功 / 人工 / 失败 / 未跑可查 |
| 部署 | 本地 / 内网，多用户与角色权限 | 数据不出域；模型本地推理 |

## 4. 使用与交付

### 4.1 三个入口

| 入口 | 适合 | 说明 |
|---|---|---|
| 单次处理 | 一份文件，先验证效果 | 默认为法律卷宗口径；可调识别范围 |
| 批量处理 | 几十到上千份，同一套口径 | 批量打码；化名需逐份走单次 |
| 供料模式 | 案卷转脱敏 Markdown 交给 AI | 单文件仅 PDF；批量供料支持 PDF / Word / 文本 / 扫描件 |

### 4.2 传统模式产物

- **打码成品**：PDF / 图片按勾选框遮盖；批量可选清晰标签、自然替换、掩码三种文本呈现，图像支持马赛克 / 模糊 / 纯色与强度、颜色设置。
- **替换成品**：同类化名或占位符，文档仍可读；文本型 PDF 经文档中转，版式可能有细微差异。
- 附**化名对照表**（供人工核对，不随成品外发）。
- 批量导出支持 ZIP 分卷与页账。

### 4.3 供料模式产物

- **脱敏 Markdown**：敏感实体替换为占位符（如 `[PERSON_1]`）。
- **映射表**：每处替换的原文、类型、占位符；可在还原工具中还原。
- **保留字段清单**：本次保留原文的字段及所在页，便于下游审计。
- 若一个敏感实体都没识别到，系统显式告警并要求确认，防止未脱敏稿直接送出。

### 4.4 当前能力边界

| 限制 | 说明 |
|---|---|
| 打码仅对 PDF / 图片开放 | Word 与纯文本请用替换 |
| 扫描件 / 图片不支持替换 | 只能打码 |
| 批量不支持化名替换 | 批量打码可用；化名逐份走单次 |
| 单文件供料仅 PDF | Word / 文本走批量供料 |
| 纯文本 / Word 无页面视图 | 只有文本对照视图 |
| 加密 PDF 需密码 | 仅用于本次解密，不保存 |
| .rtf 不予受理 | 解析会破坏中文编码 |
| 库表处理、医学影像 | 能力已具备，入口暂未开放 |

## 5. 技术与架构（对外层）

- **三条识别链路互补**：规则负责可计算的格式（证件号、电话、账号）；语义负责需要上下文的（人名、机构、称谓）；视觉负责图上的（印章、签字、证件、人脸、指印、车牌等）。文字层由 OCR / 版式解析提供。
- **本地推理**：OCR、语义、视觉全部在部署环境内运行，不依赖外部 API；可断网运行。
- **模型可替换**：模型与引擎解耦，升级或替换是权重级操作，不改业务流程。
- **确定性处置**：模型只负责"找"，"改"由规则执行——同原文同化名、掩码按规则生成、每一处替换进映射表。这是可复核、可审计的前提。
- **不公开**：端口、模型版本与代号、内部管线代号、服务拓扑不在对外材料中出现。

| E1 | 客户环境可当场复跑 | 可对外承诺 |
| E2 | 我方环境可复跑，有脚本与台账 | 可对外，必须带条件 |

| E4 | 无出处 / 已撤回 | 禁用 |

### 6.2 可对外的质量事实（E2）

- 三行业黄金语料 12 份、107 个标注实体；直接标识符 **67/67 命中**（法律 31、医疗 19、金融 17）；类型正确率 **97–100%**。
- 该语料与门槛常驻代码库，是构建门槛：识别管线改动导致 identity 召回下降即构建失败。
- 可复跑入口见公仓评测脚本（随版本演进，以仓内为准）。

### 6.3 性能：为什么不做承诺

本文**不给出**"每秒 / 每页 / 每份"的对外承诺。原因是：同一功能在不同硬件（NVIDIA / DCU）、不同文档类型、不同页密度下差异可达数十倍；任何单点秒数离开条件都没有意义。

条件化的实测记录见《性能与质量白皮书》§3，每条都绑定日期、构建与语料；其中属一次性验收的记录不得用于对外承诺。对外一律以**客户环境实测**为准。

### 6.4 已撤回 / 禁用数字

- 白皮书 v1.1 已正式撤回两组早期性能数字（「份/分钟」吞吐与「秒/份」单文件耗时），任何材料不得再用。
- 历史验收中的整卷相对提速、单页最坏值、批量份数、库表导出耗时等，均属 E3 一次性记录，仅内部参考，不进对外材料。

## 7. 差异与壁垒

| 对比对象 | 它的做法 | 墨隐的差异 |
|---|---|---|
| 人工打码 | 逐页手动，尺度不一，漏了不知道 | 同原文全文同名、可复核、页账可查、批量一致 |
| 在线脱敏 SaaS | 上传到云端处理 | 数据不出域、可断网；视觉链路（印章 / 签字 / 证件）本地做 |
| 通用大模型直接改 | 让模型读原文、直接生成"脱敏版" | 模型只找不改；改文确定性执行；映射可核；失败页隔离 |
| 拼装方案（OCR + 正则 + LLM） | 零件各自为战，没有复核与账本 | 三链路融合 + 复核工作台 + 页级账本 + 两种产物 |

一句话：**别人卖的是"打码按钮"，墨隐卖的是"可核查、可交付的链路"。**

## 8. 边界与不承诺项

### 8.1 法律边界：我们不做"匿名化"承诺

《个人信息保护法》第 73 条：匿名化是指个人信息经过处理**无法识别特定自然人且不能复原**的过程；第 4 条：匿名化后的信息不属于个人信息。

墨隐交付映射表，化名与占位符可以还原——这在法律上属于**去标识化**，不是匿名化。因此：

- 对外只用「脱敏 / 去标识化」，不用「匿名化」自我描述；
- 如客户需要匿名化（不可复原），应在交付后销毁映射表，并由客户侧完成剩余风险评估。

### 8.2 质量边界

- **不保证零漏检**：机器识别有概率漏掉特殊排版、断行、夹空格、手写、图片内文字。**人工复核与成品抽查是流程的一部分，不是可选项。**
- **不保证版式完全一致**：替换成品经文档中转可能细微重排；版式要求高请用打码。
- **不保证跨文件化名一致**：一致性只在单个文件内成立。
- **不提供法律意见**：脱敏范围是否充分由用户判断。

### 8.3 当前限制

见 §4.4。库表与医学影像能力已具备但入口未开放；批量暂不支持化名；扫描件只能打码。

### 8.4 性能边界

见 §6.3。不承诺固定耗时；以客户环境实测为准。

## 9. 术语与口径

### 9.1 术语表

| 词 | 含义 | 怎么用 |
|---|---|---|
| 脱敏 | 对敏感信息做遮蔽或替换的统称 | 对外主词 |
| 去标识化 | 处理后不借助额外信息无法识别，但借助映射可复原 | 法律 / 技术定语；我们的准确定位 |
| 匿名化 | 无法识别且不能复原（个保法第 73 条） | 只出现在边界说明，不自我描述 |
| 传统模式 | 保持原文件格式的成品交付 | 与「供料模式」并列 |
| 供料模式 | 输出 MD + 映射表 + 保留清单，供 AI 消费 | 正式材料统一叫「供料模式」 |
| 映射表 | 原文与占位符 / 化名的对照 | 与成品分开保管 |
| 保留清单 | 供料模式中选择保留原文的字段 | 只属供料模式 |
| 页账 | 页级成功 / 人工 / 失败 / 未跑记录 | 交付审计 |
| 打码 / 替换 / 化名 | 遮盖 / 换成占位符或同类词 / 替换的一种 | 不用「匿名化」代称 |

### 9.2 禁用词

- 匿名化（除 §8.1 边界说明）
- 百分百合规 / 完全合规
- 零风险 / 绝对安全 / 彻底删除 / 不可复原
- 「AI 自动脱敏，无需人工」（人工复核是流程的一部分）

### 9.3 数字使用规则

1. 只引用 E1 / E2；
2. 每个数字必须带条件（版本、硬件、语料、测量方法）；
3. 不用个案冒充基准，不把不同量纲的数字并列；
4. E3 数字只在内部台账，E4 数字禁用。
